## 概要
Kさんが参加・主催・登壇・紹介などで関わるイベントを載せる静的サイト。

* 公開URL: https://koenma777.github.io/event/
* リポジトリ: https://github.com/koenma777/event （public、ブランチ `main`）
* ホスティング: GitHub Pages（main / ルート）

## 構成
* `events.json` … 唯一のデータ元。`index.html` がこれを読み込んで描画する。
  * 項目: `id` / `title` / `date` / `end` / `deadline`（申込締切） / `place` / `kind` / `organizer` / `tags` / `comment`（Kさんのひとこと） / `note` / `url` / `image`。詳しくは README。
* `index.html` / `styles.css` / `main.js` / `schedule.js` … ビルド工程なしの静的ファイル。
  * `schedule.js` に、種別の一覧 `KINDS` と、日付・表示用の処理（`countdownLabel`、`deadlineLabel`、`googleCalendarUrl`、`icsText`、`mapUrl`、`organizerParts` など）がある。
  * 種別を増やすときは、`KINDS` に1行足し、`styles.css` に色を1行足す。
* `images/` … イベント画像、共有用の `og-share.png`、ファビコン。
  * ワークフローが保存した画像は `images/<id>.<ext>`。手で入れた画像は、内容が分かるファイル名にする。
  * ファビコンは `favicon.svg` / `favicon-32.png` / `apple-touch-icon.png`（180px）。黒い角丸の上に、パステル3色で描いた「K」とピンクの影。
* `tools/og-share.html` … 共有画像（1200×630）の元データ。イラストは Codex で描いた SVG。1200×630 でスクリーンショットして `images/og-share.png` を作る。作り直したら、`index.html` の `og:image` と `twitter:image` の末尾 `?v=` の数字を1つ上げる（今は `?v=3`）。
* `docs/event-bot.md` … イベント更新君（Grok）の指示の原本。タグ一覧もここにある。項目やワークフローを変えたら、このファイルと Grok の指示を一緒に直す。
* `docs/handoff.md` … この引き継ぎ書。
* `.github/workflows/` と `scripts/` … Issue からイベントを追加・更新・削除するワークフロー。
* ページ上部の一文（選ぶ基準）は `index.html` の `<p class="stance">` に直接書く。`description` / `og:description` / `twitter:description` も同じ文にそろえている。今の文：「九州・山口を中心に、アントレプレナー・関係人口・教育関連・人材採用のイベントをピックアップしています。」
* テスト: `node --test`（直近は34件成功）。テストは `events.json` の中身に依存しない。実データについては、種別・日付・タグの形式だけを確かめる。

## 更新の流れ（イベント更新君）
1. Grok Bot「イベント更新君」が、URL・告知文・画像を受け取って内容を1回だけ確認する。
2. ラベル `event` を付けた Issue を作る。本文には ```json の囲みで `{action: add|update|delete, ...}` を書く。
3. GitHub Actions が `events.json` を編集して main にコミットし、イベントの id をコメントしてから Issue を閉じる。
   * 実行するのは、作成者が `koenma777` の Issue だけ。
   * 画像は og:image（なければ twitter:image）を取得して `images/` に保存する（上限3MB）。
4. 終了したイベントは「これまで」に残す（消さない）。

この仕組みは変えないこと。ワークフローや Issue の書式を変えた場合は、`docs/event-bot.md` と Grok の指示も合わせて直す。

* `kind` は8種類：参加／主催／紹介／登壇／講師／メンター／審査／運営。英語の別名（`speaker`、`mentor` など）でもよい。複数当てはまるときは、いちばん中心の役割を選ぶ。
* `organizer` には主催・共催・運営の団体だけを書く。「役割 団体名」の形で、複数あれば「／」で区切る。後援・協賛は書かない。80文字以内。
* `deadline` は申込締切。形式は `date` と同じ。締切がなければ省略する。`null` を送ると消える。
* `tags` は3つまで。配列でも、`"#a #b"` という文字列でもよい。`#` は外して保存する。`docs/event-bot.md` のタグ一覧から選ぶ（テーマ：関係人口 / 地域DX / 起業 / 教育 / 採用 / キャリア / AI、対象：学生 / 社会人 / 企業向け、形式：交流会 / ビジコン / フォーラム / セミナー / ワークショップ、地域：山口 / 下関 / 福岡）。
* `comment` は200文字まで。表示は3行で折りたたみ、「続きを読む」で開く。**Kさん本人の言葉だけを入れる。Claude も Grok も、作文・言い換え・補完をしない。** なければ空のまま（表示されない）。
* 手元の画像（Kさんが送ってきたチラシなど）は、Issue からは登録できない。Claude Code で `images/` に置き、`events.json` の `image` をそのパスに書き換える。
* 外部の画像を直接読み込む指定は避ける。`images/` に保存して使う。

## デザインのルール（Kさん指定）
* 不要なサブラベルや説明は入れない。何を表しているかはレイアウトで伝える。
* bento グリッド（流行りを押さえた、見ていて楽しいもの）。
* ニューブルータリズム風で、可愛い感じ。
  * タイトル欄と各タイルに、黒い枠線（2.5px）と、右下にずらした黒いベタの影（5px、hover で8px）を付ける。角丸は24px。
  * 種別ラベル・矢印・各ボタンは、白地に黒い枠線と小さな影。画像と説明文の境目には黒い線を入れる。
  * 説明文の背景は種別ごとのベタ塗りパステル：主催 `#ffc2d4`（ピンク）、参加 `#b9f5d0`（ミント）、紹介 `#cfc6ff`（ラベンダー）、登壇 `#ffd8a8`（アプリコット）、講師 `#fff3b8`（淡い黄）、メンター `#dcf7a6`（ライム）、審査 `#f2e2c6`（サンド）、運営 `#b5e3ff`（水色）。
* フォント: 日本語は Zen Maru Gothic、英数字は Outfit（Google Fonts、weight 400/700、display=swap）。
* タイトルは「KENSEI HIRANO's EVENTS」。「下関」は付けない（下関以外のイベントもあるため）。件数は出さない。
* 日付
  * 大きな数字は「月/日」で出す（例: `11/28`）。横に小さく、年・曜日・時刻を添える。
  * 「これから」のタイルには、開催14日前から黄色 `#ffe45c` のバッジを出す（`あと○日` / `明日` / `今日` / `開催中`）。日数は日本時間の暦日で数える。
  * 申込締切は、締切前は「申込 M/Dまで」（白地に黒い枠）、締切後は「受付終了」（点線の枠と取り消し線）。
* 団体は1行に1つずつ並べる。役割（主催・共催・企画・運営 など）は小さな枠付きのラベル、団体名は太字。役割ラベルは種別ラベルより小さく、影は付けない。
* タグは、団体名の下に `#タグ` の形で小さく1行で出す。枠は付けない。
* ひとこと（`comment`）は、タイトルの下に黒い枠の白い吹き出しで出す。左端に「K」の丸い印を付ける。
* 見出しの下に、選ぶ基準の一文（stance）を出す。空なら出さない。
* 方針：このサイトはイベント一覧ではなく「Kさんが選び、関わっているもの」を見せる場。らしさの中身は、見た目より「何を選んだか・なぜ心が動いたか」。
* 「これから」のタイルの左下に、「カレンダーに追加」（Google カレンダーか .ics を選べる）と「地図」（会場名で Google マップを開く）のボタンを置く。オンラインだけのイベントには地図ボタンを出さない。
* レイアウト
  * PC（1024px以上）は3列、タブレット（700〜1023px）は2列、スマホは1列。全タイルを同じ大きさ・同じ高さにそろえる。
  * 画像の枠は 16:10。object-fit: cover で、上端の中央を基準に切り取る。タップすると `<dialog>` のライトボックスでチラシ全体が開く。
  * チラシは縦長の画像を使う。横長のバナーしかない場合は、公式のチラシから表面を切り出す。
* タイルに出す情報: 種別・日付・タイトル・ひとこと（あれば）・団体・タグ。画像がないタイルには、加えて会場とメモも出す。
* 「これまで」も同じスタイル。ただし背景はグレーのベタ塗りで、画像は白黒。「ありません」の欄は黒い点線の枠。
* hover でタイルを少し傾ける。フェードインは、opacity を最初から1にして、位置だけを動かす。
* 返答・UIの文言は日本語。

## 作業環境のメモ（Claude Code クラウド）
* このリポジトリ用に、個人環境「event」がある。許可している通信先は yamagucheers.com と wired.jp（Kさんが設定画面で追加）。ほかのサイトが必要なときは、Kさんに環境の Edit → Allowed domains で追加してもらう（Claude からの変更申請は拒否されることがある）。本番サイトや SNS には通信できないので、本番の表示はKさんに確認してもらう。
* クラウドのセッションは、Mac の CPU やファイルを使わない。Codex のように Mac にしかないツールは使えない。
* Mac のフォルダ（Projects / Company / 00_ClaudeCode）は、Remote Control の一覧に出ているが、クラウドからは使えない（2026-11-25 時点）。Mac のセッションに作業を頼むときは、依頼文を Mac 側に直接貼る。
* Google カレンダーと Gmail のコネクタが使えるので、イベント候補を探すときに使える。
* GitHub への書き込みが 403 で拒否されたら、Kさんに GitHub の再接続を頼む。
* 作業用ブランチ以外のブランチは、この環境から削除できなかった（接続が途中で切れる）。不要なブランチは、Kさんに GitHub の画面で消してもらう。
* 強制プッシュは、自動モードで拒否される。マージ済みのブランチを作り直すときは、リモートのブランチと main が同じ内容か、main の方が新しいことを確かめてから `git merge -s ours` で取り込み、それから作業する。
* main には、イベント更新君や Cursor のコミットも入る。作業を始める前に、必ず最新の main を取り込む。
* マージはKさんの指示を受けてから行う。方法はスカッシュマージで統一している。
* PR の通知を登録するときは、PR を作ったときに返ってきた実際の番号を使う。
